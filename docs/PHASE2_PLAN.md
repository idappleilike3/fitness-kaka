## 2. 功能總表（是否每日 AI／成本／優先）

| 功能 | 使用者怎麼用 | 每天自動呼叫 AI？ | 對公司成本 | 對收益影響 | 開發優先 |
|------|--------------|-------------------|------------|------------|----------|
| 語音飲食紀錄 | 傳 LINE 語音 → 確認後才存 | **否**（傳才算） | 中（Whisper＋Chat；有每日上限） | 提高付費意願；支撐 399／799 | **P0** |
| 進階健身建議 | 產出／查看課表與建議 | **否**（建議每週 1 次或使用者點「產生」） | 低（優先**模板**；少用大模型） | 提高續訂、支撐 799 | **P1** |
| LIFF 7 天圖表 | 開 LIFF 看熱量／營養趨勢 | **否**（讀 DB 畫圖） | **很低** | 明顯提高留存 | **P0** |
| LIFF 30 天圖表 | 同上，拉長區間（偏 799 或付費） | **否** | **很低** | 支撐高價方案感 | **P1** |
| 體重趨勢分析 | 記錄體重＋折線圖 | **否**（讀 DB） | **很低** | 提高留存與信任 | **P0** |
| 信用卡定期定額 | 每月自動扣 399／799 | **否**（金流排程） | 手續費約 2.8% | **穩定月收、降流失** | **P0**（資格到位才做） |

### 明確不做（避免傷收益）

| 不做 | 原因 |
|------|------|
| 每天自動幫「每一位」會員跑長篇 AI 分析 | OpenAI 成本會隨人數線性爆炸 |
| 免費開語音 | 免費用戶刷 Whisper 易虧損 |
| 語音／文字共用同一個額度池 | 難控「免費不能用語音」 |
| 用影片算熱量 | 貴、慢、不準；影片留給 Phase 3 Form Check |
| 每人每天客製 AI 課表 | 成本高、運動傷害風險高 |

## 3. 各功能詳細規劃

### 3.1 語音紀錄（P0）

**流程：**  
語音 → 查**語音額度** → 下載音檔（≤60 秒）→ Whisper 轉文字 → 飲食 JSON 分析 → pending → 確認後寫入。

**額度（與文字分開扣）：**

| 方案 | 語音／天 |
|------|----------|
| 免費 | 0 |
| 399 | 5 |
| 799 | 15 |

**API：** 同一把 `OPENAI_API_KEY`（Whisper + Chat）。  
**收益注意：** 只有使用者主動傳語音才計費；上限控成本。

**Phase 1 過渡文案：** ~~收到語音回「正式版開放」~~ → **已改為真實語音流程**；收到影片仍只提示照片／文字／（付費）語音。  
**語音上線後：** 影片提示已含語音訊息；**799 已上架銷售**。

> **實作狀態（2026-07-23）：** 語音紀錄（Whisper → 飲食分析 → pending 確認）與 `plan_799` 建單／LIFF 雙方案按鈕 **已完成**。其餘本檔功能（圖表、體重、定期定額、健身模板）仍待開發。

---

### 3.2 進階健身建議（P1）

**策略：模板優先，AI 精修為輔。**

1. 依 `goal_type`（減脂／增肌）+ 訓練場景（居家／健身房）+ 每週頻率 → 選模板  
2. 輸出：一週天數、部位、動作、組數、次數、休息、有氧建議、飲食提醒（短）  
3. 可一週最多重新產生 1 次（或 799 每週 2 次）  
4. **不要**每天自動重生  

**免責：** 非醫療／物理治療；疼痛即停；特殊族群建議專業人士。

**收益注意：** 幾乎不傷 OpenAI；主要增加開發與內容維護成本。

---

### 3.3 LIFF 7 天／30 天圖表（P0／P1）

**資料來源：** `daily_nutrition_summary`、`meal_records`（已存在的加總）。  
**實作：** 折線／長條（熱量、蛋白）；不呼叫 Vision。  

| 方案 | 歷史圖表 |
|------|----------|
| 免費 | 當日（維持 P1） |
| 399 | **7 天** |
| 799 | **30 天**（可規劃到 90 天屬 Phase 3 再拉） |

**收益注意：** 成本可忽略；強烈建議做，因提高「每天打開看」的習慣。

---

### 3.4 體重趨勢（P0）

- LINE 或 LIFF 輸入體重 → `weight_records`  
- LIFF 折線圖（7／30 天與方案對齊）  
- 可選：較上次增減；**不做誇大減重承諾**  

**收益注意：** 幾乎無 AI 成本；有助續訂。

---

### 3.5 信用卡定期定額（P0，資格門檻）

**目標：** 取代「每 30 天要使用者再付一次」的流失。

| 項目 | 規劃 |
|------|------|
| 方案 | 399／799 月訂 |
| 權威 | 仍以藍新伺服器通知為準 |
| 成功 | 延長 `expires_at` +1 個計費週期 |
| 失敗 | 通知使用者、寬限期（如 3 天）、之後降回免費額度 |
| 取消 | LIFF 說明如何取消；取消後用至期末 |

**若資格未到位：** 維持一次付 30 天 + 到期前 3 天／1 天提醒續購（不挡 Phase 2 其他功能）。

**收益注意：** 手續費約 2.8%，但續訂率上升通常**淨收益更好**。

## 4. 會不會「每天分析」？會不會影響收益？

### 簡答

- **語音／健身／圖表／體重／定期定額 → 都不是「每天自動對所有人跑貴 AI」。**  
- 圖表與體重：幾乎不花 OpenAI。  
- 語音：用才花，且有每日上限。  
- 健身：每週／按需，模板為主。  
- 定期定額：幫助穩定收月費。

### 成本 vs 收益（概念）

```
營收 ↑（續訂、799、語音賣點）
成本 ↑（語音 Whisper 有限增加；圖表≈0；金流 2.8%）
→ 設計正確時，Phase 2 應提高「每付費用戶貢獻」而非吃掉利潤
```

**傷收益的做法（禁止）：** 全員每日自動長報告、免費語音、無上限語音。

## 5. Phase 2 建議開發順序

1. LIFF 7 天圖表 + 體重紀錄／趨勢（快、留存高、成本低）  
2. 語音紀錄 + 額度 + 上架語音文案；399 開語音；評估上架 799  
3. 30 天圖表（綁 799 或付費）  
4. 模板健身建議  
5. 定期定額（資格 OK 再做）；否則先強化到期提醒
