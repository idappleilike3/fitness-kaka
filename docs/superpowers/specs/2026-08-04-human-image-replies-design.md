# 卡卡人性化圖片回覆設計

## 目標

LINE 使用者傳送任何圖片時，卡卡先像真人一樣回應畫面內容，再提供與圖片或問題相關的下一步。只有明確包含可分析食物或飲料的圖片才建立餐點預覽並扣除圖片餐點分析額度。

## 圖片類型與行為

- `food`：先自然說出看見的餐點，再顯示營養估算與確認按鈕；成功辨識後才扣圖片額度。
- `person`：友善回應照片情境，不批評外貌、體型或推測健康狀況，不扣額度。
- `exercise`：回應正在進行的活動，詢問是否需要運動或飲食建議，不扣額度。
- `pet`、`scenery`、`life`、`product`：針對畫面自然聊天並提出一個貼近情境的問題，不扣額度。
- `screenshot`：簡短說明看見的是截圖或文字資訊，詢問使用者想解讀、整理或判斷哪一部分，不扣額度。
- `unknown`：誠實表示無法確定內容，請使用者補充想問什麼，不編造餐點，不扣額度。

## 處理流程

1. LINE webhook 下載圖片後交給圖片理解服務。
2. OpenAI 以單次結構化輸出回傳 `kind`、自然回覆 `reply`，食物時另回傳完整營養資料。
3. 非食物立即回覆 `reply`，不讀取或扣除餐點額度。
4. 食物才嘗試扣除圖片額度；額度不足時回覆額度提示，不建立餐點。
5. 額度足夠時記錄 API 使用量、建立待確認餐點，依序送出自然回應與營養預覽。
6. AI、資料庫或 LINE 發送失敗時，沿用全站錯誤處理；若食物額度已扣除但後續失敗，退回額度。

## 安全與語氣

- 回覆使用繁體中文、1 至 3 句、溫暖自然，不輸出「分類結果」等機器措辭。
- 不根據照片推測年齡、疾病、族群、性別認同或其他敏感屬性。
- 人像不做身材羞辱或未經要求的減肥評論。
- 截圖不宣稱已確認其中資訊真偽；需要時請使用者說明問題。
- 圖片可能同時有人與食物；只要餐點清楚且使用情境合理，可歸為 `food`，但自然回覆仍不得評論人物外貌。

## 驗收

- 食物圖片：自然開場、營養預覽、扣一次額度、建立一筆待確認餐點。
- 自拍、運動、寵物、風景、生活、商品、截圖、未知圖片：自然回覆、不扣額度、不建立餐點。
- 非食物圖片即使餐點額度已用完，仍能獲得正常回覆。
- 圖片理解失敗不扣額度；食物辨識後的儲存失敗會退款。
